FIELD NOTES / LLM INFERENCE

An inference engine, built from first principles

How does a language model turn your message into a reply?

I’m building an inference engine—the software that runs a trained language model—in Mojo, on an Apple Silicon Mac. Follow the work from text to GPU computation, and see what makes a reply faster and checkable.

The question behind the project

I’m a mathematician learning systems programming and GPU computing by building a working inference engine.

How much of a modern inference engine can I build, understand and measure on a MacBook?

Mojo lets the text processing, model and GPU kernels share one language. The project keeps the working code, measurements and unsuccessful experiments in the open.

What makes a reply faster?

A faster GPU operation may save little time in a complete reply. Compare an accepted optimization with a promising candidate that missed its measured goal.

How do we check a change?

Independent numerical tests compare results. Measurements test speed. Compile-time checks reject particular invalid token-selection plans before execution.

What works, and what comes next.

As of October 16, 2026
Working chat

A conversation runs locally on the Mac’s GPU.

The native Mojo engine turns messages into token IDs, runs Qwen2.5-0.5B-Instruct, and streams the reply. Model weights and previously computed context stay loaded between turns.

Serving core

Several requests can share the computation.

The core schedules requests, manages their stored context, handles cancellation, and can recompute under memory pressure. Its recorded walkthrough uses a reference execution path; a multi-request frontend and prefix caching remain future work.

Open research

Can different schedules give exactly the same result?

Processing the same prompt in different chunk sizes can change floating-point arithmetic. Exact agreement for the full model remains open. The small host compile-time example checks one selection step; it does not establish GPU or full-model correctness.
